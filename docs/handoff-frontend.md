# 给前端同学：VelaPet 端侧业务与 AI 对接清单

日期：2026-11-03。范围：当前 SiFli-SDK / RT-Thread 产品仓库。对接方：端侧软件与云端 API 接入负责人 → LVGL 前端负责人。

## 1. 本次目标与当前基线

首个联调目标：用户点击快捷消息，端侧取得真实业务快照，经网络发送到后端，在 LVGL 线程显示 DeepSeek 中文回复。图片先使用内置默认形象；真实 Seedream 生图暂缓，开关保持关闭。

当前主代码在个人 fork 的本地 `member-4/cloud-chat-assets` 分支；新增功能尚未提交、推送或合入共同仓库。请先核对各自基准，不直接用旧版本文件覆盖当前代码。

| 内容 | 状态 |
| --- | --- |
| `src/app/velapet_core.*` 宠物、任务、成长规则 | 已有纯 C 实现；应用状态服务和正式 UI 绑定待做 |
| `host/ai-backend/` 聊天、人设、最近六轮会话 | 已实现并通过本地测试；本轮 DeepSeek 真实短文本调用 1 次通过 |
| 三款默认形象及选择保存 | 电脑端已实现；尚未部署到手表 |
| 照片任务、资源下载及校验 | 代码和本地替身/demo 流程已有；Seedream 真实调用 0 次 |
| 手表 AI 服务、正式聊天页、中文字库 | 尚未完成跨模块集成 |

17 项后端测试和电脑端冒烟通过，不代表手表显示或整机联网闭环已通过。电脑端 Tk 工具是联调工具，不是交付的手表页面。

## 2. 接口语言与权威定义

最新共同仓库 `06f922e` 已明确跨线接口只能通过 `velapet_service_*`、`vp_net_*`、`vp_storage_*`、`vp_diag_*`。本说明中后续业务快照/动作归入前端线的 `velapet_service_*`；云端协议归后端线 `vp_net_*`，不新增另一套跨线 bridge ABI。任何正式接口变更需对方线评审及项目负责人批准。

- 手表内模块：C 函数、结构体、枚举，统一 `.h` 声明。
- 设备与后端：HTTP/HTTPS + JSON；照片上传使用 multipart/form-data，由 AI 服务处理。
- 前端不直接调用供应商 API、不保存 DeepSeek/方舟 Key，不解析 ESP AT 命令。
- 当前权威业务头文件：[velapet_core.h](../src/app/velapet_core.h)。`velapet_state_t` 是唯一业务真值。
- 旧 NuttX 的 `vela_pet_api.h`、`PetProfile`、pthread bridge、`S:` 和 `/data/agent/...` 不是当前产品 ABI。

现有 core 函数是纯规则函数，调用方需要传入状态和日期，不自带全局互斥或线程生命周期管理。正式 UI 应通过前端业务线将实现的 `velapet_service_*` 获取快照、提交动作，不自行维护或并发修改全局业务状态。

## 3. 我们提供什么

### 已有代码与资源

1. 业务状态和规则；任务类型为每日步数、连续运动、签到、社交，状态为未开始、进行中、完成待领奖、已领奖。
2. 后端快捷聊天、自定义文字、人设、会话 ID 和清除会话功能。
3. `nova-cat` 星云猫（缺省）、`biscuit-dog` 奶油犬、`mint-rabbit` 薄荷兔。
4. SVG 源文件：[assets/source/default-pets](../assets/source/default-pets)。PNG 导出工具：[export_default_pets.py](../host/ai-backend/tools/export_default_pets.py)。
5. 电脑端可独立验证的聊天和形象工具，见 [电脑端指南](ai-desktop-guide.md)。

### 我们接下来实现，接口待共同评审

以下只是接口职责草案，**当前还没有对应正式 C 头文件和可链接实现**。名称、字段布局、错误码与生命周期评审后再统一提供，不要求前端自行补一份兼容实现。

| 接口职责草案 | 预期语义 |
| --- | --- |
| 业务快照读取 | 复制到调用者缓冲区，包含宠物、任务和状态版本；前端只读 |
| 业务动作提交 | 签到、领奖、切换已解锁皮肤；返回成功、已处理或错误 |
| AI 请求提交 | 接收快捷类型或转写文本，立即返回请求 ID 或 BUSY/OFFLINE/INVALID 等结果 |
| AI 结果获取 | 按请求 ID 提供回复文本、来源、人设/会话 ID、情绪、错误状态 |
| 展示取消/页面退出 | 停止向该页面投递；底层请求是否能取消取决于网络层，旧请求结果不得覆盖新请求 |
| 外观资源事件 | 提供已验证可读的资源 ID、版本、设备本地路径；前端在线程内刷新 |

我们负责队列、HTTP、序列化、超时、会话管理和结果生命周期。前端负责页面、按钮和合法 UI 上下文中的显示。AI 回复不能直接覆盖等级、经验、任务或奖励。

## 5. 数据和线程契约建议

### 业务字段

| UI 信息 | 当前 core 字段/函数 |
| --- | --- |
| 名称、等级、经验 | `name`、`level`、`exp`、`exp_to_next` |
| 累计步数、连签 | `total_steps`、`consecutive_days` |
| 当前及已解锁皮肤 | `current_skin`、`unlocked_skins`、`unlocked_skin_count` |
| 今日任务 | `tasks[]` 的 `type/target/progress/exp_reward/status` |
| 称号 | `velapet_get_title()` |

当前 task 没有 description 字符串，前端按 type 映射文案；今日真实步数尚不能直接从累计步数或封顶任务进度推导。名字和皮肤为定长数组，不要改成指针布局。

### AI 文本

- 快捷类型：`greeting`、`cheer`、`task`、`level`；自由文字/未来语音转写走 `custom`。
- 后端 message 最多 240 个 Unicode 字符，max_chars 可取 16～80，手表建议请求 50。
- 字符数与 UTF-8 字节数不同。C 缓冲应按最坏情况规划，例如最多 80 字符的纯回复至少预留 321 字节含 NUL；完整 JSON 另算。
- 结果含 `reply`、`source`、`error_code`、`intent`、`emotion`、`conversation_id`、`persona_id`。
- `source=local_fallback` 即降级文案，HTTP 200 不一定代表云模型成功。
- 不根据收到回复直接加经验；后端 reward 只是建议，端侧尚未实现最终持久化去重规则。

### UI 生命周期

所有 LVGL 操作，包括图片解码/缓存失效，在前端认可的 UI 上下文内执行。消息跨线程传递使用有界复制数据或明确所有权的句柄；不把临时字符串/悬空控件指针跨线程保留。页面退出可缓存结果，再进入时重新绑定新控件。

## 6. 默认图片与后端接口

默认素材为透明 RGBA PNG：avatar 128×128、home 240×240、skin 160×160，需按真机解码能力调整。skin 是资源用途名，不表示已注册成长皮肤。AI 生成流水线目前是浅色不透明 RGB PNG，两者不能混淆。

默认外观选择目前保存于后端 SQLite；手表本地选择保存和离线恢复还未完成。设备应能使用随固件部署的默认图，无需开机联网下载。

| 已实现 HTTP 接口 | 用途 |
| --- | --- |
| POST `/api/v1/chat` | 快捷/自由聊天 |
| GET `/api/v1/personas` | 人设列表 |
| DELETE `/api/v1/conversations/{id}?device_id=...` | 清除会话 |
| GET `/api/v1/default-pets` | 默认资源清单 |
| GET `/api/v1/default-pets/{id}/{kind}.png` | 默认 PNG |
| GET/PUT `/api/v1/appearance` | 查询/保存默认形象选择；GET 带 device_id，PUT 为 JSON |
| GET `/api/v1/image-capabilities` | 查询生图开关 |

这些 HTTP 接口供电脑联调和未来 AI 服务使用，LVGL 页面不直接写 HTTP。详情见 [默认图片说明](default-pets-and-images.md)。Seedream 保持关闭，不需要前端发真实生图请求来验收本轮。
