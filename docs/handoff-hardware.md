# 给硬件/主工程同学：VelaPet 端侧 AI 平台接口对接清单

日期：2026-11-03。目标平台：黄山派 SF32LB52-ULP，SiFli-SDK / RT-Thread。对接方：端侧软件与云端 API 接入负责人 → 驱动、平台及主工程负责人。

## 1. 当前目标和已知状态

首个目标：手表快捷消息经现有网络访问 VelaPet 后端，取得一条真实 DeepSeek 回复并交给 UI。第二目标：可靠保存业务状态和默认表宠资源。语音转写随后接入，Seedream 真实生成暂缓。

用户已确认板子有联网功能。旧仓库文档曾记载 ESP-01S/PAN 尚未验证，该记录不能代替最新状态；本次需要的是实际链路、软件 API 和验证证据，不预设必须采用 ESP-01S。

目前电脑端后端与资源流程已有，17 项本地测试通过；本轮一次 DeepSeek 真实请求成功。我们未在当前机器构建或烧录固件：固定版本 SDK 环境尚未配置，无板端网络/存储/麦克风实测。本地代码仍在个人 fork 分支，未提交、推送或创建 PR。

## 2. 职责和接口语言

按共同仓库 `06f922e` 的最新分工，跨线交互限定为：`vp_net_*` 由后端定义协议、硬件实现传输，`vp_storage_*` 由前端业务线定义语义、硬件实现介质，`velapet_service_*` 由前端业务线定义并实现，`vp_diag_*` 由硬件定义实现。下述能力草案应纳入这些接口，不另造临时跨线 ABI；正式变更需对方线评审和负责人批准。

| 层级 | 实现责任 |
| --- | --- |
| 宠物、任务、成长规则与状态模型 | 我们，`src/app/` |
| 应用状态服务、AI 协议、请求队列、超时与资源同步 | 我们，`src/app/`、`src/services/` |
| 驱动、实际联网、TLS能力、存储、时间与录音适配 | 硬件/平台方，`src/drivers/`、`src/platform/`、相关 `src/services/` |
| 显示、字体、图片组件与 UI 线程更新 | 前端与主工程共同负责 |
| DeepSeek/Seedream API 与供应商密钥 | 我们的 Python 后端，设备只使用独立设备 Token |

手表内部接口用 C 语言；设备访问后端用 HTTP/HTTPS + JSON，未来图片上传为 multipart/form-data。当前权威业务头文件为 [velapet_core.h](../src/app/velapet_core.h)，禁止复制第二套状态定义。

本文件的网络/存储/录音接口是能力契约草案，**没有新增正式 `.h`，也不表示这些适配器已经实现**。请优先提供现有 SDK/产品 API，我们在其上适配；接口评审后只保留一份权威头文件。

## 4. 网络服务最小契约（待评审）

希望提供传输无关的能力，不要求 UI 或业务层理解 AT、BLE、具体 UART 和 Socket 细节。

| 能力 | 约定方向 |
| --- | --- |
| 状态查询/事件 | 未就绪、连接中、就绪、掉线；就绪区分仅链路连接与可访问后端 |
| 请求输入 | 固定后端 origin、方法、路径、请求头、正文/长度；不向任意地址发送设备 Token |
| 响应输出 | 传输错误与 HTTP 状态码分离；返回实际长度，文本缓冲 NUL 终止，截断必须报错 |
| 时限 | 连接、读写/操作和总等待均有界，不只依赖单次读超时 |
| 生命周期 | 单请求或可重入、是否串行、句柄归属、关闭和取消方式明确 |
| 大文件 | 流式读写，不能把完整照片或生成图片装入线程栈 |
| 断线 | 清理连接、释放资源、返回稳定错误；AI 服务决定重试，付费生成不盲目重发 |
| TLS | 明确 MCU/模块/其他哪层负责，校验证书和主机名，明确可信时间来源 |

首轮只需支持 GET `/health` 和 POST `/api/v1/chat`。HTTPS 的证书及主机名校验不能关闭。HTTP 仅用于隔离局域网开发；正式链路使用 HTTPS。现有 BLE GATT 诊断读写不自动等于 HTTP 传输；如已有自定义中继，请交付协议及配套端程序。

我们提供 JSON 编解码和业务状态机，平台方无需实现模型人设或供应商协议。请求/响应缓冲最终上限需双方测量后确认，不能沿用旧 pthread bridge 的栈值。

## 5. 存储与时间契约（待评审）

### 小状态与图片资源分开

业务状态可通过 KV/FlashDB 或文件保存；图片需要明确的资源区或可写文件系统。配置启用了 FlashDB/文件系统模块不代表实际分区可读写。

请提供：分区容量、可用空间、最大单文件/对象、擦写限制、读取方式，以及掉电恢复保证。建议有界探测：创建临时对象 → 写入 → 读取比对 → 同步 → 重命名替换 → 重启验证 → 清理测试对象。不要格式化未知分区。

业务保存需带数据版本并支持迁移；新记录完整写入前保留上一有效版本。资源先下载到临时位置，校验大小/SHA-256，再原子替换或切换活动版本。KV 无文件 rename 时需给等效双槽/事务方案。

设备资源根目录和 LVGL 映射以真机方案为准；旧 `/data/agent/...`、`S:` 不能直接视为规范。服务端不指定设备绝对存储路径，只给资源 ID、用途、版本、大小、哈希和相对下载 URL。

### 日期与传感器

core 的 `day_id` 是调用方提供的本地日历日编号，同日保持一致，跨日增加；未知值用已有定义 `VELAPET_DAY_UNKNOWN`。需要明确 RTC 未设置、校时向后、时区和重启恢复策略；不要用“开机秒数/86400”假装日历日期。

步数接口需明确累计还是增量、计数器溢出/重启/清零，避免重复累加。连续运动需明确中断判定，仅累加零散分钟不能证明连续达标。我们据此定义应用服务输入，不直接把传感器示例值当真实上下文。

## 6. 图片、内存和中文显示

当前默认候选：星云猫、奶油犬、薄荷兔。源素材位于 [assets/source/default-pets](../assets/source/default-pets)，本地导出为透明 RGBA PNG：128×128 头像、240×240 主页、160×160 预览。可先随固件资源部署，离线启动不应依赖后端下载。

240×240 RGBA 仅解码像素约 225 KiB，还未包含 PNG 临时缓冲、绘制缓冲、页面、TLS、JSON 和缓存。请提供：

- 内部 RAM 与 PSRAM 的可分配区和使用限制。
- 当前运行时空闲/最小剩余堆、线程栈高水位。
- PNG/透明度、图片转换为 SDK 原生格式的能力与实测。
- LVGL 文件系统/资源管理器是否已注册，实际图片读取例子。
- 中文字体存储和加载方案，是否支持完整字库或按需加载，与前端共同确认。

当前配置主线程为 4096 字节；这不是 AI 线程预算，更不是整机可用内存。我们会使用独立有界任务，不在 LVGL 线程进行网络等待，也不直接搬用旧工程的 64 KiB pthread 栈。

## 7. 语音接入的后续材料

第一步先快捷消息。后续语音链路：按键录音 → PCM → ASR 转写 → 可确认/编辑的文字 → 现有 custom 聊天 → 回复显示。麦克风注册或录音成功不等于语音识别已经实现。

请提供录音 API、数据所有权、采样率/位深/声道、缓冲回调、溢出行为、停止/取消、最大时长、原始 PCM 样例（不含私人对话）、音频链路测试证据。ASR 模型/服务、预算和是否采用上传音频方案由我们与用户另行决定；暂不增加 TTS 播放范围。

## 9. 分阶段验收与回传模板

1. 平台 GET `/health` 成功，记录网络类型、DNS/IP、HTTP状态；该接口成功仅证明可访问后端，不证明模型可用。
2. 从板端发送固定测试上下文，收到 `/api/v1/chat` 的 source=deepseek 回复；记录状态和耗时，不泄露密钥。
3. 断网/超时/重连时资源释放、UI不中断，宠物离线业务仍可用。
4. 默认图片读取和反复切页无持续内存增长；实际显示、触摸和中文质量标为人工验收。
5. 存储写入/同步/替换/重启恢复验证后，再做业务状态保存和图片同步。
6. 最后进入录音和 ASR；Seedream 仍按用户当前要求暂不实测。
