# 外观资源字典（Appearance Registry）v1.1

> 状态：**冻结口径**，全组统一引用。
> 背景：后端反馈"烧录进手表的皮肤/形象与后端不对应"。根因不是固件烧错——手表端显示的
> 名称列表是前端先行内置的本地静态数据（为让 UI 先跑起来），此前**没有任何共享文档定义
> 皮肤/形象的机器 ID 与中文名映射**，导致后端/Web 平台无从对齐。本字典即为该契约的正式
> 冻结版本，任何端改动都必须走 PR 并通知全组。

> 显示名 v1.1 修订（v1 旧名"初始/运动蓝/烈焰红/星河紫/彩虹"对照见 §2.2）；
> 主题装扮构成：晨跑=蓝头带+运动场、火花=火焰应援、星夜=星月巫师帽+星空、泡泡=彩虹泡泡+欢呼。

- 真机启用真图需同时满足三个编译条件：`VELAPET_UI_SKIN_IMAGES=1`、

- 数据流向：按 `host/web/docs/API_INTEGRATION.md`（§设备快照），皮肤信息由**设备快照
  上报**，Web/AI 侧不得修改。

## 2. 形象（Pet Avatar）— 唯一主角 + 角色池（v1.1 修订）

**v1.1 修订背景**：素材核对确认 5 套皮肤图为**同一只黄色电气鼠 × 5 个主题装扮**
（配饰/背景不同），而 v1 时代固件形象页列出的"星云猫/奶油犬/薄荷兔"三个物种
**没有任何素材**，属纯文字占位 —— 三物种并列会被误解为"可换宠物"。据此把形象
体系收敛为「唯一主角 + 后续角色池」：

### 2.1 当前主角：伏伏（FuFu，`fufu`）

| 项 | 定值 |
|----|------|
| 角色 ID | `fufu` |
| 物种/设定 | 元气电气鼠 —— 精力过剩、好奇心强、爱表现；主人步数给它"充电"，越爱运动越活泼 |
| 角色 DNA（全主题恒定） | 明黄主体 `#FFD44D`、深棕耳尖、粉腮红、闪电形尾、大头小身 |
| 默认形象 | 伏伏·日常（`skin_id = default`） |

角色 DNA 锁定是 AI 生图管线（"预设打底、只改用户要的点"）的契约基础：
主题只换配饰与背景，角色本色不变。

### 2.2 显示名统一规则（覆盖 v1 旧名）

主题显示名统一为 **「伏伏 · 双字主题词」**，`skin_id` 机器 ID 不变（零契约破坏）：

| skin_id | v1 旧显示名（废） | v1.1 显示名（现行） |
|---------|------------------|--------------------|
| `default` | 初始 | **伏伏 · 日常** |
| `sport_blue` | 运动蓝 | **伏伏 · 晨跑** |
| `flame_red` | 烈焰红 | **伏伏 · 火花** |
| `star_purple` | 星河紫 | **伏伏 · 星夜** |
| `rainbow` | 彩虹 | **伏伏 · 泡泡** |

> 汇报页另一套素材名（默认电气鼠/晨跑冲刺/火花开怀/星夜小巫师/泡泡飞跃）同步废止，
> 统一收敛到上表，避免"一套素材两套名字"。
> **固件同步待办**（前端）：`ui_common.c` 显示名表、`ui_avatar.c` 形象页文案按本表
> 更新；中文子集字体需重生成并校验"伏"字覆盖。

### 2.3 后续角色池（原"星云猫/奶油犬/薄荷兔"归位）

| pet_id | 中文名 | 状态 |
|--------|--------|------|
| `fufu` | 伏伏 | **现行主角**，素材已入库 |
| `nebula_cat` | 星云猫 | 角色池：素材未到位；到位后**自带一套主题皮肤组**上线 |
| `cream_dog` | 奶油犬 | 同上 |
| `mint_rabbit` | 薄荷兔 | 同上 |

切换角色 = 整组换形象（角色 + 该角色全部主题）；**不做**三物种同屏文字占位。
形象与皮肤是两个维度：皮肤 = 同一角色下的场景外观；角色 = 宠物本体。

### 2.4 点击/切换交互约定（与演示页同步）

- 换肤：250ms 淡入淡出，不做整图跳动；
- 单击：局部开心反应（耳弹 + 尾加速 + 腮红亮 + 小电花），真机由"开心跳"帧组驱动；
- 双击：欢快模式 2 秒（挥手 + 头摆 + 尾大幅快摆），真机由"跳舞"帧组驱动；
- 整身缩放/位移仅作帧序列之上的节奏微调（如呼吸 ±4%），不作为动作主体。

## 3. AI 定制皮肤（扩展规则）

- 用户经 AI 生图产出的定制皮肤，`skin_id` 命名规范：`ai_<14位时间戳>`，
  例：`ai_20261124173000`。
- 定制皮肤图片规格与内置皮肤一致（整帧 220×176 JPG + 缩略 120×96 JPG），
  经文件系统下载通道下发（内置 5 款不依赖文件系统）。
- 内置 `skin_id`（上表 5 个）为保留字，AI 生成结果不得占用。

## 5. 变更流程

1. 任何新增/改名/删除，开独立分支改本文件，提 PR；
2. PR 中 @ 全组（尤其后端与 Web），合并后各方同步各自实现；
3. 设备端固件改名属于**破坏性契约变更**，需后端同步改 schema 后同批合并。
