# 外观资源字典（Appearance Registry）v1

> 状态：**冻结口径**，全组统一引用。
> 背景：后端反馈"烧录进手表的皮肤/形象与后端不对应"。根因不是固件烧错——手表端显示的
> 名称列表是前端先行内置的本地静态数据（为让 UI 先跑起来），此前**没有任何共享文档定义
> 皮肤/形象的机器 ID 与中文名映射**，导致后端/Web 平台无从对齐。本字典即为该契约的正式
> 冻结版本，任何端改动都必须走 PR 并通知全组。

## 1. 皮肤（Skin）— 5 款，已内置

`skin_id` 为唯一机器 ID，全端（固件 / Web 平台 / 后端 / AI 生图）以此为准；
中文名仅用于展示，不得作为 key 传输。

| # | skin_id | 中文名 | 整帧场景图 | 缩略图 | 状态 |
|---|---------|--------|-----------|--------|------|
| 1 | `default` | 初始 | `skin1.jpg` 220×176 JPG | `skin1_t.jpg` 120×96 JPG | 已内置固件 |
| 2 | `sport_blue` | 运动蓝 | `skin2.jpg` | `skin2_t.jpg` | 已内置固件 |
| 3 | `flame_red` | 烈焰红 | `skin3.jpg` | `skin3_t.jpg` | 已内置固件 |
| 4 | `star_purple` | 星河紫 | `skin4.jpg` | `skin4_t.jpg` | 已内置固件 |
| 5 | `rainbow` | 彩虹 | `skin5.jpg` | `skin5_t.jpg` | 已内置固件 |

- 图片源文件位于 `docs/assets/skin/`（仓库内）；编译期由 `scripts/gen-skin-images.js`
  转为 C 数组（`src/ui/ui_skin_img_data.h`）。
- 真机启用真图需同时满足三个编译条件：`VELAPET_UI_SKIN_IMAGES=1`、
  `LV_USE_SJPG=1`（LVGL v8 内含 TJpgDec）、`LV_IMG_CACHE_DEF_SIZE>=1`。
  任一不满足 → 显示几何替身，但**名称列表仍然显示上表**（名称是硬编码，与图片开关无关）。
  后端复现"名称对不上图"时，先确认固件编译开关，再谈数据口径。
- 数据流向：按 `host/web/docs/API_INTEGRATION.md`（§设备快照），皮肤信息由**设备快照
  上报**，Web/AI 侧不得修改。

## 2. 形象（Pet Avatar）— 3 款

前端此前只有中文名、没有机器 ID，本次一并冻结 `pet_id`：

| # | pet_id | 中文名 | 状态 |
|---|--------|--------|------|
| 1 | `nebula_cat` | 星云猫（默认） | 名称已内置固件；整帧形象图为**云端资源**（handoff 第 6 节），外观资源事件接口评审接入后再接 |
| 2 | `cream_dog` | 奶油犬 | 同上 |
| 3 | `mint_rabbit` | 薄荷兔 | 同上 |

注意：形象与皮肤是**两个独立维度**。皮肤 = 场景外观（背景/配饰/配色）；形象 = 宠物角色。
组合关系（哪个形象配哪套皮肤）由后续外观资源事件接口定义，本字典不预设。

## 3. AI 定制皮肤（扩展规则）

- 用户经 AI 生图产出的定制皮肤，`skin_id` 命名规范：`ai_<14位时间戳>`，
  例：`ai_20261124173000`。
- 定制皮肤图片规格与内置皮肤一致（整帧 220×176 JPG + 缩略 120×96 JPG），
  经文件系统下载通道下发（内置 5 款不依赖文件系统）。
- 内置 `skin_id`（上表 5 个）为保留字，AI 生成结果不得占用。

## 4. 各端引用位置

|----|------|------|
| 手表固件 | `src/ui/ui_common.c`（g_skin_ids / names 表）、`src/ui/ui_skin_image.c`（ui_skin_ids）、`src/ui/ui_avatar.c`（pet_names，pet_id 待补常量） | 前端维护 |

| 后端 / 协议 | 待冻结（组员四）：建议在 BLE_SYNC_PROTOCOL v1 外观资源事件与设备快照 schema 中引用本表 | 组员四 |
| AI 生图 | 生图请求/结果中的 skin_id 遵循 §1/§3 | 组员四 |

## 5. 变更流程

1. 任何新增/改名/删除，开独立分支改本文件，提 PR；
2. PR 中 @ 全组（尤其后端与 Web），合并后各方同步各自实现；
3. 设备端固件改名属于**破坏性契约变更**，需后端同步改 schema 后同批合并。
