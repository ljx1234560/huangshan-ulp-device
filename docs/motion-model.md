# VelaPet 运动模型体系设计

- 版本：v1.1（2026-11-24）
- 范围：黄山派板载加速度、角速度、芯片计步、磁场、环境光五路数据在 VelaPet 中的建模、任务奖励映射和提醒体系
- 当前实现：`src/app/velapet_motion.h/.c` 是**可独立运行、通过主机单测的算法核心**；当前产品固件尚未启用传感器框架与 I²C3，没有真机运动功能
- 不在本文范围：具体采样驱动实现、真实阈值标定、烧录与真机验收、云端训练
- 传感器证据与 SDK 封装风险以 `docs/motion-sensor-inventory.md` 为准

## 1. 目标与非目标

**目标**

1. 把传感器数据压缩成少量稳定、可解释的活动事件。
2. 让运动数据成为任务系统、经验等级、宠物状态和提醒功能的唯一输入。
3. 在无网络、无文件系统、低功耗的条件下仍可独立工作。
4. 业务规则可主机单测、可回放、可交接。

**第一版（v1）范围**

- **必需输入**：三轴加速度 + 芯片计步累计值。
- **暂不参与判定**：角速度、磁场、环境光。陀螺默认关闭；光照判佩戴默认关闭（`light_dark_raw=0`）；磁场不进 v1。
- 芯片计步未达到精度目标前，不声称步数可信；也不实现加速度自主计步降级。

**非目标**

- 不使用机器学习或云端推理做步态识别。
- 不在 P0/P1 实现加速度自主计步；是否实现由 FE-2 真机误差结果决定（见 19 节）。
- 不在端侧保存原始波形，不保存个人位置、心率等敏感数据。
- 不在 P0 阶段实现陀螺手势或户外识别。

## 2. 设计原则

| 原则 | 含义 |
| --- | --- |
| 确定性 | 阈值 + 滞回状态机，同样输入得到同样输出，可回放 |
| 计步优先 | 芯片计步器为主数据源，加速度只做强度、静止和异常校验 |
| 单一真值 | 活动状态由运动模型产出，业务状态只由 `velapet_service` 修改 |
| 事件驱动 | 模型输出事件与增量，不在内部直接调用 UI、存储或网络 |
| 证据优先 | 芯片计步与阈值必须经真机实测后才能宣称可信；当前只有合成轨迹单测 |
| 最小降级 | 光照未标定时关闭非佩戴判定；传感器故障时停用运动提醒，不伪造数据 |
| 防打扰 | 提醒受佩戴、时段、冷却和每日上限约束 |

## 3. 总体架构

```text
LSM6 加速度 ┐
LSM6 角速度 ┤
LSM6 计步器 ├── vp_sensor_*（第五跨线接口，有条件批准）
MMC56 磁场  │        采样适配器 + 1 秒特征帧
LTR303 光照 ┘              │
                           v
                  velapet_motion_*（手表端，平台无关）
                  活动状态机 / 计步增量 / 计时器 / 事件
                           │
                           v
                  velapet_service_*（手表端业务服务）
                  任务进度 / 经验奖励 / 快照 / 提醒事件
                     │                         │
                     v                         v
              LVGL 页面与动画            震动 / RGB / 按键
                     │
                     v
              vp_storage_*（持久化，P2）
```

线程建议：一个运动任务线程负责采样、调用 `velapet_motion_*` 和上报服务；UI 只在 LVGL 线程读取快照和消费提醒事件；运动模型本身不做线程同步，由单一线程独占。

## 4. 传感器输入与采样配置

| 数据 | 板载器件 | 用途 | 建议采样 | v1 |
| --- | --- | --- | --- | --- |
| 加速度 X/Y/Z（mg） | LSM6DS3TR-C | 活动强度、静止判定、异常校验 | 25 Hz，±4 g | **必需** |
| 芯片计步（16 位累计） | LSM6DS3TR-C | 步数主数据源（待实测语义） | 2 s 轮询 | **必需** |
| 角速度 X/Y/Z（mdps） | LSM6DS3TR-C | 手势、翻转唤醒、行走置信度 | 默认关闭；交互后 10–20 s | 不用 |
| 磁场 X/Y/Z | MMC5603NJ | 方向辅助、标定检查 | P2，按需 | 不用 |
| 环境光（原始计数） | LTR-303ALS-01 | 非佩戴辅助、自动亮度、户外任务 | 1 Hz | 不用（阈值前关闭判佩戴） |

采样适配器（`vp_sensor_*`）的职责：设备打开与异常重开、采样节拍、**单调毫秒时间戳**、原始单位转换、有效/无效样本标记，把数据送入运动模型。它不判断活动语义。

### 4.1 需要产品侧适配的 SDK 封装风险

固定 SDK 的传感器封装不能直接视为可信输入（详见 `docs/motion-sensor-inventory.md`）：

1. MMC5603NJ 的 Z 轴读取越界，磁场 v1 不启用，启用前必须安全适配。
2. LTR-303 的 `light` 是 CH1 原始计数，单位标为 lux 但未换算；只能当原始值。
3. LSM6 轮询未完整检查底层错误；适配器必须区分有效样本与 I²C 失败，失败样本不得喂给模型。
4. RT-Thread 传感器 `timestamp` 在启用 RTC 时分辨率只有秒；运动模型必须使用适配器自记的单调毫秒时间戳。
5. 板上器件为 LSM6DS3TR-C，SDK 封装名为 LSM6DSL；正式采集前核对器件 ID、寄存器与采样配置。

当前生成配置未启用 `CONFIG_RT_USING_SENSOR` 与 `CONFIG_BSP_USING_I2C3`，产品固件没有注册上述传感器。**启用配置、取得诊断证据是 P0 的前置门禁。**

## 5. 端侧数据管线

### 5.1 一秒特征帧

模型内部对每个自然秒聚合：样本数、`|a|` 均值、`|a|` 方差（标准差阈值比较）。没有样本的秒不推进活动计时，避免传感器暂停时误判久坐。

### 5.2 分钟统计窗口

- **活动分钟**：一分钟内活动（轻活动或行走）秒数达到阈值，记 1 个活动分钟。
- **行走会话**：连续行走累计满 60 秒记 1 个行走分钟；中断超过配置时间后丢弃未满一分钟部分。
- **久坐**：静止且佩戴时累计；行走或 60 秒内步数达到阈值时清零。

### 5.3 步数环形缓冲

模型保存最近 60 秒的每秒步数，用于断坐判定与活动强度参考，避免额外保存完整波形。

## 6. 活动状态机

```text
                步数增量在保持窗口内
       STILL ───────────────────────> WALKING
         ^  |                            |
         |  | 无步且加速度安静            | 连续无步超过中断时间
         |  v                            v
         +────────────────────────── LIGHT（有动作、无步）
```

| 状态 | 判定 | 业务含义 |
| --- | --- | --- |
| `UNKNOWN` | 尚无有效数据 | 不计时、不提醒 |
| `STILL` | 加速度标准差低于静止阈值且无步 | 久坐计时；非佩戴判定 |
| `LIGHT` | 加速度高于活动阈值但无步 | 手部活动，不计行走；暂停久坐计时 |
| `WALKING` | 最近一次步数增量在保持窗口内 | 连续行走、活动分钟、断坐 |

- 进入活动使用较高阈值，退出使用较低阈值（滞回），避免临界抖动。
- 计步保持窗口默认 10 秒，用于跨过计步器 2 秒轮询间隔和短暂停步。
- 非佩戴：长时间静止 + 光照低于暗阈值。默认光照阈值 0，即未标定前不启用；非佩戴时暂停久坐与久不运动提醒，并清零久坐计时。

## 7. 计步模型

1. 首次读取只建立基线，不计步。
2. 增量使用 16 位无符号差：`delta = (uint16_t)(now - last)`，天然处理 65 535 回绕。
3. 单次增量超过 500 步视为计数清零或异常，丢弃并重建基线。
4. 每日步数、待上报增量分开保存；上报采用 30–60 秒批量，减少 UI 刷新和存储写入。
5. 重启后重新建立基线；已持久化的当日步数不重复计算。
6. 跨天由上层 RTC 提供 `day_id` 触发 `velapet_motion_reset_day()`。

待真机验证：是否会读后清零、重启是否归零、计数上限与回绕行为。

## 8. 运动事件

| 事件 | 触发 | 消费方 |
| --- | --- | --- |
| 步数增量 | 计步增量累计 | 业务服务批量记步 |
| `ACTIVE_MINUTE` | 一分钟活动达标 | 新增活动任务、经验 |
| `WALK_MINUTE` | 连续行走满一分钟 | 连续步行任务 |
| `SEDENTARY` | 佩戴且静止达到久坐阈值 | 久坐提醒、断坐任务 |
| `INACTIVITY` | 白天连续无步达到阈值 | 久不运动提醒 |

事件是位掩码，读取即清除；步数增量独立取走。提醒的升级、冷却、安静时段和每日上限由业务服务层实现，模型只报告"计时到点"。

**消费规则（防止慢消费丢次）**：同类型事件在两次读取之间会合并为一位。因此：

- 步数用 `velapet_motion_take_steps()` 增量，可累计，不丢。
- 活动分钟、行走分钟**不得只靠事件位计数**；业务服务必须用 `velapet_motion_status()` 中的 `active_minutes_today`、`walk_minutes_today` 单调计数差值入账，或保证运动任务至少每秒排空一次事件。
- `SEDENTARY`、`INACTIVITY` 是提醒边沿，合并为一次提醒可接受。

## 9. 业务映射：任务、经验、奖励

| 任务 | 数据来源 | 目标 | 经验 | 状态 |
| --- | --- | --- | --- | --- |
| 今日步数 | 步数增量 | 3000 步 | 20 | 已实现 |
| 连续步行 | 行走分钟计数差值 | 10 分钟 | 30 | 已实现 |
| 每日签到 | 按钮 | 1 天 | 10 | 已实现 |
| 互动打卡 | 聊天/互动 | 1 次 | 15 | 已实现 |
| 每日活动 | 活动分钟计数差值 | 30 分钟 | 25 | 待扩展 |
| 久坐打断 | 提醒后规定窗口内达到断坐步数 | 4 次 | 15 | 待扩展 |

规则：

- 扩展任务需要把 `VELAPET_TASK_COUNT` 从 4 调整为 6，并同步 UI、持久化 schema、单测。
- 单日经验设上限，步频钳制（≤250 步/分钟），跨天重置。
- 宠物"精力/情绪"由运动快照实时派生驱动动画，不写入第二套持久化真值。
- 久坐打断奖励以"提醒后 10 分钟内累计 30 步"为完成条件，由业务服务结合提醒事件与步数增量判定。

## 10. 提醒体系

| 提醒 | 触发条件 | 重复 | 解除条件 |
| --- | --- | --- | --- |
| 久坐 | 佩戴、静止 45 分钟、活跃时段（08:00–21:00） | 每 +45 分钟，单日最多 3 次 | 行走或 60 秒内 30 步 |
| 久不运动 | 佩戴、连续 2 小时无步 | 每次无步周期一次 | 任意步数增量 |
| 断坐奖励 | 久坐提醒后 10 分钟内达到 30 步 | 单日计入任务 | — |

共同约束：

- 冷却 30–60 分钟；安静时段 21:00–08:00；非佩戴不提醒。
- 输出分级：UI 气泡 → 短震动 → RGB 呼吸；按键支持"稍后"。
- 每次提醒必须可关闭、可追溯，且不阻塞 LVGL 线程。
- 需要 RTC 提供本地小时；无 RTC 时按"相对时间 + 默认白天"降级，并在文档中标注不确定性。

## 11. 数据与持久化

P0 阶段文件系统尚未打通，运动状态先放内存，重启后重新计步；P2 通过 `vp_storage_*` 保存聚合数据。

建议持久化字段：

```c
typedef struct {
    uint32_t day_id;
    uint32_t steps;
    uint16_t active_minutes;
    uint16_t walk_minutes;
    uint8_t  sedentary_breaks;
    uint32_t last_step_counter;  /* 重启基线参考 */
    uint32_t total_active_minutes; /* 终身累计 */
} vp_motion_day_record_t;
```

- 每 1–5 分钟或跨天时原子写入，不保存每秒原始数据。
- 退出前刷新一次；写入失败保留内存值并重试。
- 断电恢复后以持久化步数为准，计步器重新建基线。
- 恢复接口待补：`velapet_motion_restore_day()`（当前 v1 只能从零开始当日计数）。

## 12. 接口契约

### 12.1 跨线接口 `vp_sensor_*`

状态（2026-11-24）：项目负责人**原则同意**列为第五个跨线接口，属有条件批准；评审方提出的 3 点修改尚未归档，确认后写入正式契约并更新 AGENTS.md。在此之前实现方按本节签名开发，但不得对外宣称已冻结。

AGENTS.md 原规定端侧只允许 `vp_storage_*`、`velapet_service_*`、`vp_net_*`、`vp_diag_*` 四个接口；本接口由硬件线实现采样，手表端消费并定义语义。

```c
/* 由设备侧实现，运动任务调用。返回 0 成功。 */
int vp_sensor_motion_start(uint32_t accel_hz, uint32_t step_poll_ms,
                           uint32_t light_hz);
int vp_sensor_motion_read_accel(int32_t *x_mg, int32_t *y_mg, int32_t *z_mg,
                                uint32_t *timestamp_ms);
int vp_sensor_motion_read_steps(uint16_t *counter, uint32_t *timestamp_ms);
int vp_sensor_motion_read_light(uint32_t *raw, uint32_t *timestamp_ms);
int vp_sensor_motion_stop(void);
```

约定：

- 只做采样与时间戳，不做活动判定。
- 失败必须返回明确错误码，由调用方决定降级。
- 不阻塞调用方超过一个采样周期。

### 12.2 `velapet_motion_*`（已实现 v1）

见 `src/app/velapet_motion.h`。关键行为：

- `velapet_motion_init(motion, config, now_ms)`，`config` 可为 NULL 使用默认值。
- `velapet_motion_feed_accel()` 单样本 mg；`velapet_motion_feed_steps()` 16 位累计值；`velapet_motion_feed_light()` 原始计数。
- `velapet_motion_tick()` 每秒推进时间；`velapet_motion_take_steps()` 取增量；`velapet_motion_take_events()` 取事件位。
- `velapet_motion_status()` 输出活动状态、佩戴状态、当日计数与久坐秒数。
- `velapet_motion_reset_day()` 跨天清零但不重置计步基线。

默认参数：

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `still_std_mg` | 25 | 静止标准差上限 |
| `moving_std_mg` | 45 | 进入活动阈值 |
| `walk_hold_ms` | 10000 | 行走保持窗口 |
| `walk_break_ms` | 180000 | 行走会话中断 |
| `active_seconds_per_minute` | 20 | 活动分钟阈值 |
| `sedentary_limit_ms` | 45 分钟 | 久坐阈值 |
| `inactivity_limit_ms` | 2 小时 | 久不运动阈值 |
| `sedentary_reset_steps` | 30 步/60 秒 | 断坐步数 |
| `nonwear_still_ms` | 10 分钟 | 非佩戴静止时长 |
| `light_dark_raw` | 0 | 0 表示关闭光照判佩戴 |

## 13. 线程与生命周期

| 阶段 | 动作 |
| --- | --- |
| 启动 | 初始化模型；读持久化日记录；采样适配器建基线 |
| 运行 | 运动线程 40 ms 喂加速度；2 s 读计步；每秒 tick；光照/陀螺按需 |
| 事件消费 | 业务服务每秒排空步数与事件；分钟任务用计数差值，提醒用边沿事件 |
| 跨天 | RTC 给出新 `day_id` → 服务日切 → 模型日切 |
| 停止/重启 | 刷持久化；重建计步基线；不补发历史提醒 |

模型函数非线程安全，必须单线程调用；快照与提醒事件跨线程时由业务服务加锁或投递到 UI 队列。

## 14. 功耗

| 场景 | 配置 |
| --- | --- |
| 常亮/交互 | 加速度 25 Hz；计步 2 s 轮询；光照/陀螺按需（P2） |
| 熄屏 | 加速度 12.5 Hz 或 SDK 低功耗模式；陀螺关闭；计步保持 |
| 手势/唤醒 | 陀螺短时 10–20 s，结束后立即关闭 |
| 磁场 | P2 前不常开 |

使用 FIFO 批量读取，避免高频 I2C 轮询；震动提醒控制单次 ≤200 ms；具体电流和续航需要真机测量。

## 15. 异常与边界

| 情况 | 处理 |
| --- | --- |
| 时间戳回退 | 重置秒边界，不补算，记录一次异常 |
| 采样中断 | 空秒不推进活动计时；恢复后继续 |
| 长时间无有效样本（>60 s） | 服务暂停运动提醒并显示"传感器不可用"；恢复后重置计时，不补发提醒 |
| 计步跳变/清零 | 丢弃增量并重建基线 |
| 传感器打不开 | 运动模型不启用；步数显示沿用持久化值；UI 提示不可用 |
| I²C 读失败 | 适配器丢弃该样本并上报错误计数，不得把旧值当新值 |
| 光照未标定 | 关闭非佩戴判定 |
| 无 RTC | 提醒使用相对时间，安静时段降级 |
| 存储未打通 | 仅内存运行，重启后从零计当日步数 |

## 16. 验证体系

0. **采样门禁（先于一切运动功能）**：产品固件启用 `RT_USING_SENSOR` 与 `BSP_USING_I2C3`，注册 LSM6DS3TR-C 加速度/计步；有界诊断命令输出设备 ID、单位、单调毫秒时间戳、读取错误与采样间隔。未取得该项证据前，不宣称真机运动功能。
1. **主机单测**：已覆盖计步回绕/清零、久坐与断坐、行走/活动分钟、非佩戴、日切；输入为合成数据。
2. **轨迹回放**：真机录制 `monotonic_ms, ax, ay, az, steps, light, read_ok`，转换为 C 数组或 CSV，回放断言状态与事件序列。至少覆盖静置、已知 100/500 步、原地摆臂、上下楼、摘下、重启、长时间缺样本。
3. **诊断命令**（硬件线实现）：`diag motion watch <s>`、`diag motion dump <s>`、`diag step watch <s>`、`diag reminder test`。
4. **标定协议**：已知 100/500 步走行、静止 10 分钟、抖手 5 分钟、摘下 10 分钟、明暗切换，记录误判；阈值需至少 3 名佩戴者数据。
5. **验收指标**：步数误差 ≤5%（500 步）；久坐检测延迟 ≤2 分钟；缺样本/故障时不误提醒；分钟事件在慢消费下不丢次。

## 19. 风险与待决策

1. 计步器语义未验证（读后清零、重启归零、上限），是 P0 最大风险；未验证前步数只能标为演示值。
2. 当前产品固件未启用传感器框架与 I²C3，且没有 `vp_sensor_*` 适配器或运动任务线程；算法核心不等于真机功能。
3. 加速度阈值与光照暗阈值需要至少 3 名佩戴者标定；现有 7 组单测使用合成轨迹。
4. 是否实现加速度自主计步：由 FE-2 的芯片计步误差决定；误差 ≤5% 时沿用芯片计步，否则再立项。
5. SDK 封装存在 MMC 越界、LTR 单位错误、LSM6 错误检查不足、秒级时间戳等缺陷，采样层必须先适配。
6. 慢消费时事件位会合并；分钟任务必须走计数差值，否则会少记。
7. 无心率/GPS，"强度"只能是相对等级，不宣称卡路里或户外里程。
8. `VELAPET_TASK_COUNT` 变更会影响持久化 schema、UI 和单测，需要一次性迁移。
9. 文件系统 BLOCKED，P2 前不能承诺重启不丢步数。
10. 提醒依赖 RTC 本地时间，时区与跨天策略需与业务服务统一。
11. 震动马达驱动与电流预算仍 PENDING，提醒强度待真机确认。
